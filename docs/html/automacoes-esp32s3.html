Automações com o ESP32-S3

O S3 deixa de ser só gravador e vira o assistente de campo da base: registra a sessão pelo celular, avisa quando algo dá errado, reconhece marcos já medidos e entrega os dados prontos para um pipeline que devolve coordenadas SIRGAS2000 sem intervenção.

01

Resumo: o que vale fazer primeiro

1F2

Sessão de ocupação pelo celular

Portal cativo no Wi-Fi do S3 recebe ponto, altura medida duas vezes, antena e operador, e grava session.json ao lado do UBX. Elimina a ficha em papel e alimenta o convbin no escritório.

2F5

Painel de saúde com alarmes

Tempo ocupado contra as metas de PPP (2,5 h / 4 h), satélites, lacunas, antena e jamming (UBX-MON-RF), SD e bateria.

3O1 · O2

Descarga automática

Por cabo, o S3 vira pendrive (TinyUSB MSC) [G1]. Pelo Wi-Fi do escritório, um script baixa os arquivos novos com verificação SHA-256 [G2, G3].

4O3 · O4

Pipeline sem intervenção

UBX → RINEX → API do IBGE-PPP [G5] → SIRGAS2000 → banco de sítios. Em paralelo, PPK com download automático pela API RBMC [G6].

5F3

Ciclo fechado

As coordenadas PPP voltam ao S3 (sites.csv). Na próxima visita a base reconhece o marco e se configura em modo fixo, sempre com confirmação humana.

6F7 · F11

Conexões alternativas ao Bluetooth

S3 como cliente NTRIP via hotspot do celular e NMEA por TCP ao SW Maps ("NMEA over IP" no Android e iOS [G7] trecho de busca). Exige a regra de uma única fonte de RTCM.

O que o formulário captura

  • Código do ponto e tipo de marco.
  • Altura 1 e altura 2, com alerta se diferirem mais de 3 mm HIPÓTESE; vertical ou inclinada; ponto de referência (ARP).
  • Antena (lista com nomes IGS), operador, observações.
  • No encerramento: nova medição de altura e resumo (duração, % de épocas, satélites, alarmes).

O portal abre sozinho por DNS e DHCP opção 114 no Android, iOS e Windows; não redireciona HTTPS [G2]. Os metadados do RINEX (-hm, -hd, -ha, -hr) saem do session.json sem digitação.

Regra de ouro: uma única fonte de RTCM

F7 · cliente NTRIP no S3

  • Estação mais próxima: sourcetable (registros STR com lat/lon HIPÓTESE) ou API RBMC relatorio/{estacao} [G6].
  • Failover por lista ordenada e reconexão exponencial.
  • GGA do NAV-PVT a cada 10 s, se exigido.
  • Grava o RTCM recebido (*.rtcm3) para PPK de contingência.
  • Credenciais no NVS, nunca no SD.

F11 · NMEA por TCP

Servidor TCP (SparkFun usa 2948 [G9]) envia GGA/RMC/GST. Habilitar CFG-MSGOUT-NMEA_ID_GGA_UART1 (e RMC/GST) e CFG-UART1OUTPROT-NMEA=1 [F11]. O S3 grava tudo e repassa ao TCP só as linhas NMEA.

F12 · hora GNSS

Relógio do S3 por settimeofday() a partir do NAV-PVT [G12]; resposta NTP no softAP para notebook, controle do drone ou câmeras. Precisão de ms; TIMEPULSE num GPIO melhora HIPÓTESE.

F6 · eventos

Sem EXTINT: botão grava o tempo do último NAV-PVT (ms). Com EXTINT: UBX-TIM-TM2 com o tempo da borda [F2 §3.13.2], convertido pelo convbin em evento flag 5 no RINEX [F1].

07

Escritório

O1 · pendrive USB

Porta USB nativa do devkit. Ao detectar o host: fecha o arquivo, pausa a gravação, expõe o MSC. Em campo, a gravação não depende disso (power bank não enumera como host HIPÓTESE).

O2 · descarga por Wi-Fi

GET /manifest.json (nome, tamanho, SHA-256 calculado no S3) → baixa novos → confere hash → POST /ack. Exclusão no S3 só com ack, idade mínima e falta de espaço.

O5–O8

Git com perfis e hash em cada sessão; OTA com rollback, confirmando a versão só após autoteste (UART com UBX válido, SD montado) [G4b]; relatório MD/PDF + GeoPackage; sites.csv de volta com validação de esquema.

O3 · pipeline com a API do IBGE-PPP

Parâmetros documentados [G5] trecho de busca, conferir antes de codificar: arquivo, tipo-levantamento, modelo-antena, altura-antena (m, ponto decimal, marco → ARP), marco-ibge, email, autorizacao-uso. Resposta JSON com URL do resultado.

import json, requests
s = json.load(open("session.json"))
files = {"arquivo": open(s["rinex211_zip"], "rb")}
data = {"tipo-levantamento": "estatico",            # conferir grafia aceita na doc
        "modelo-antena": s["antena_igs"],
        "altura-antena": f'{s["altura_arp_m"]:.4f}',
        "email": "geodesia@luftplan.example"}
r = requests.post("https://servicodados.ibge.gov.br/api/v1/ppp", files=files, data=data, timeout=600)
r.raise_for_status(); resultado = r.json()          # guardar JSON bruto junto da sessão

O4 · PPK automático

  • Estação mais próxima via …/api/v1/rbmc/relatorio/{estacao} (cache local) [G6].
  • Estático: …/rinex2/{estacao}/{ano}/{dia} (15 s).
  • Cinemático/drone: …/rinex3/1s/{estacao}/{ano}/{dia}/{hora}/{minuto}/{tipo}.
  • .conf gerado do modelo do v1; sinalizar |ΔH| > 3 cm ou |ΔV| > 6 cm contra o IBGE-PPP.

CSRS-PPP como controle

A NRCan oferece web, "PPP Direct" e um script de submissão automática distribuído sob pedido [G13] trecho de busca. Pedir o script, ou manter o CSRS manual por amostragem (1 a cada 5 sessões).

08

Arquitetura de firmware modular

Regras invioláveis: (1) o sd_logger grava todos os bytes; (2) configuração só em RAM, sempre verificada; (3) uma fonte de RTCM; (4) rede e web com prioridade menor que gravação; (5) credenciais no NVS; (6) falha de rede nunca para a gravação (watchdog reinicia o módulo, não o chip).

Referências: ESP-IDF (Apache-2.0) e exemplos [G1–G4]; espressif/mdns [G3]; SparkFun u-blox GNSS v3 3.1.15 (MIT) [G8] se o projeto for em Arduino-ESP32; NTRIP do esp32-xbee é GPL-3.0 [F9].
